# Budget page / Expense form (가계부)

> CLAUDE.md에서 이동된 상세 내용. 이 영역을 작업하기 전에 먼저 읽을 것.

- **Budget page** (`budgetPage.js`, route `#/budget/:id`, PRD v6 "가계부 기능"; entered from the SHELL's bottom tab 가계부 (`tripShell.js`'s `MYTRIP-BOTTOMTABS`) — moved there from the schedule page's own quick menu, which used to hold this button; a full page not a modal, with no `←` back button any more (the `일정` tab is now how you get back to `#/schedule/:id`)): reuses the schedule page's "여행준비 + Day1~DayN" structure (`util.getTripDays`), one section per Day plus `prep`, each showing that day's `expenses` as one-line cards (category icon + title + amount, e.g. `$45`) with a `+ 비용 추가` button; a fixed bottom bar sums every loaded expense's `krw_amount` (e.g. `₩ 1,234,000`). An expense whose `day_key` matches no current Day (e.g. the trip's dates changed after it was recorded) is not dropped — it lands in a trailing "그 외" section. Loading follows the schedule page's pattern: a loading line before the first load (`storage.isExpensesLoaded`), the cache drawn immediately on later visits and refreshed behind it (`storage.loadExpenses`), a toast on failure (e.g. before `005_budget.sql` is run). `+ 비용 추가` opens `expenseForm.js`; `budgetPage.js` calls `expenseForm.init(refreshVisible)` once so a successful save re-renders the currently visible budget page straight from the cache (no re-fetch needed, since `addExpense` already pushed the row into it).
  - **Swipe-delete** (each `.budget-item` wrapped in `.budget-item-wrap`/`.budget-item-delete-bg`): the same gesture as the schedule timeline's swipe-delete (`timelineDrag.js`) — not the main page's trip-card swipe, which instead reveals a fixed amount and opens a confirm dialog, since deleting an entire trip is a much bigger blast radius than one expense. `budgetPage.js` implements its own pointer handlers directly (no shared module; `timelineDrag.js` also carries the drag-to-reorder gesture this screen has no use for) — swiping the card body left past `SWIPE_START_PX` commits to a swipe, the card tracks the pointer 1:1, and crossing half the card's width (`SWIPE_DELETE_RATIO`) deletes immediately (no confirm step), animating the card off-screen and the wrapper's height/margin down to 0 before calling `storage.deleteExpense(id)`. A capture-phase one-shot `click` swallower (`suppressNextClick`, same trick as `timelineDrag.js`/`mainPage.js`) stops a mouse's post-swipe `click` from reopening the edit form. Both success and failure (e.g. RLS rejecting someone else's expense) re-render the budget list from the cache via the existing `refreshVisible()` (a toast shows the failure first) — same "always re-render after, success or failure" pattern as the schedule timeline's `onDelete`.
  - **`budget-header` 우측 아이콘 2개** (`.budget-header-actions`, `budget-header-text`가 `flex:1`이라 자연히 우측에 붙는다; 둘 다 `.mytrip-icon-btn`/`--dark`를 그대로 재사용한 SHELL과 같은 둥근 아이콘 버튼이다 — 가계부 전용 레이아웃을 새로 만들지 않았다): 총 지출(pie 아이콘, `data-action="show-total"`)과 1/n(아이콘 대신 글자 그대로, `data-action="show-split"`). 둘 다 `budgetPage.js`에서 직접 여는 모달이고(각자 쓰는 파일이 따로 없다 — `tripShell.js`의 exit-confirm 모달과 같은 패턴), 보이는 가계부 화면을 벗어나면(`router.onLeave("budget", ...)`) 둘 다 닫는다.
    - **총 지출** (`BUDGET-TOTAL`): 지금 여행의 모든 지출을 `category`로 묶어 `krwAmount` 합을 내림차순 정렬하고, 전체 합 대비 퍼센트(`Math.round`)와 막대(`.budget-category-bar-fill`)로 보여준다. 막대 채움색은 새 색을 만들지 않고 이미 있는 파스텔 블루(`--dday-pastel-bg`, D-day 배지와 같은 색)를 재사용한다 — 카테고리마다 다른 색이 필요한 다색 세트가 아니라 "채워진 정도"만 보여주는 장식 요소라서다. `expenseCategoryData.js`의 7개 키(`flight/lodging/transport/meal/shopping/tour/etc`)를 쓰지, `myTripData.CATEGORY_META`/`--cat-color`(6개, 다른 키 집합)는 섞지 않는다.
    - **1/n** (`BUDGET-SPLIT`): 멤버별 정산액 = (그 멤버가 결제자로 들어간 지출의 `krwAmount`/결제자 수 합) − (그 멤버가 더치페이로 들어간 지출의 `krwAmount`/더치페이 인원 수 합) — `expense.payerIds`/`splitIds`(둘 다 복수 선택 가능, `expenseForm.js` 참고) 그대로 쓴다. 양수면 "받을 돈"(`--text-accent`, 블루), 음수면 "보낼 돈"(`--text-danger`, 레드) — 새 색상 역할을 만들지 않고 CLAUDE.md 글자색 6역할의 블루/레드 계열을 그대로 쓴다. 멤버 이름은 `storage.loadMembers(tripId)`를 열 때마다 새로 불러온다(`tripMembers.js#withSelf`/`expenseForm.js#withSelf`와 같은 방식으로 내 이름만은 로그인 정보로 보강한다). `expenseForm.js`의 "+ 추가"로 넣은 비회원 인원은 이름이 서버에 전혀 남지 않으므로(그 지출의 `payerIds`/`splitIds`에 uuid만 저장되고 이름은 폼을 닫으면 사라진다) "이름 없는 멤버"로 보인다 — `tripMembers.js`가 같은 상황을 처리하는 방식과 같다.


- **Expense form** (`expenseForm.js`, a modal opened from the budget page, not a route; one entry point for both add and edit, like `schedule.js#openForm`): implements all of PRD v6 5-1 through 5-7.
  - 5-1 currency + amount: a custom dropdown lists up to 3 choices formatted "국가 - 기호(한글명)" (KRW, USD, and the trip's destination currency, deduped if it's already KRW/USD). **PRD v12(여행지 확장) 이후 분기** (`expenseForm.js#currencyOptions`): `trip.destinationId`가 있으면 `currencyData.getCurrencyOptionsByCode(trip.currency, country)`로, 확정해 둔 ISO 코드를 그대로 쓴다(13개국 큐레이션 표 밖의 코드는 기호·한글명 자리에 코드 자체가 들어간다, `trip.currency`가 `null`이면 — 통화를 모르는 나라 — 원화·달러 2개만). `destinationId`가 없으면(국내·옛 방식) 예전 그대로 `getCurrencyOptions` — `trip.destination`의 마지막 콤마 뒤 나라 이름을 `currencyData.js`의 13개국 표와 맞춰본다.
  - 5-2 day: a toggle dropdown (`.expense-day-picker`/`-trigger`/`-list`), built exactly like the currency picker below it rather than showing every Day at once; a single `document` click listener closes whichever of the day/currency dropdowns is open when the other's trigger (or anything outside both) is clicked, so opening one auto-closes the other.
  - 5-3 payment method: two radios (cash/card).
  - 5-4 title, 5-7 memo (optional, no validation).
  - 5-5 category: `expenseCategoryData.EXPENSE_CATEGORIES` (7) as `.expense-category-item`s (circular icon on top, small label below, `.expense-category-item--active` fills the circle with `--accent`) in a `nowrap`/`overflow-x: auto` row (`.expense-category-chips`) so they scroll horizontally instead of wrapping.
  - 5-6 members: `storage.loadMembers(tripId)` (same call as `tripMembers.js`, with the same `withSelf` fallback for my own name/photo when 003 hasn't run), rendered as `.expense-member-header`/`.expense-member-row` sharing one `grid-template-columns: 32px 1fr 40px 40px` so the "결제"/"나누기" header labels line up with every row's two checkboxes; both are plain multi-select checkboxes, read at submit time (`collectMemberIds`), not tracked in JS state. A `membersRequestId` counter (mirrors `tripMembers.js`'s `manageRun`) drops a stale members fetch if the form is closed/reopened first.
  - **Required**: amount, day, payment method, title, category (`.form-error`, save button disabled while saving, modal stays open on failure — same pattern as `schedule.js`'s form). Members and memo are optional.
  - **Add vs edit**: `open({ trip, dayKey })` opens it empty for a new expense on that day; `open({ trip, expense })` (from clicking a `.budget-item` card) pre-fills every field, including checking the payer/split boxes from `expense.payerIds`/`splitIds`, and changes the title to "비용 수정". On submit it computes `krwAmount` via `currencyData.toKrw` and calls `storage.updateExpense(expense.id, payload)` when editing, else `storage.addExpense({ tripId, ...payload })`.
