# Invite (초대)

> CLAUDE.md에서 이동된 상세 내용. 이 영역을 작업하기 전에 먼저 읽을 것.

- **Invite** (`invite.js`, markup `#invite-overlay` in `index.html`; accepting is `invitePage.js`):
  - **Trigger and link**: the SHELL's right slide-in menu (`MYTRIP-MENU`, see **Trip shell**) has a `여행 공유` item, owner-only since only `getTrip().role === "owner"` can read/insert `trip_invites` under RLS — `tripShell.js`'s `renderMenuList` decides whether to render it, so there is no separate `refresh()` to call (the old `#invite-row`/`invite.refresh()` pair, called from `app.js#renderTripHeader`, is gone; `invite.js` exports `open` instead). Clicking it calls `invite.open()`, which opens a modal and immediately (inside the click, so Safari allows it) starts `getInviteUrl(tripId)`: reuse a `trip_invites` row with `expires_at > now`, else insert a new 8-char code (31-letter alphabet without look-alikes, `crypto.getRandomValues`, retries on unique violation 23505; `expires_at` defaults to 7 days in the table).
  - **Copy**: the URL is `location.origin + location.pathname + "#/invite/<code>"`, copied with `navigator.clipboard.write([new ClipboardItem({"text/plain": promise})])` (falls back to `writeText`), toast "링크가 복사되었어요". If the copy has not settled after 2.5 s (e.g. the document has no focus) the modal asks the user to copy the link by hand. The modal also shows the link in a readonly input with a 링크 복사 button (fallback for http addresses without the clipboard API).
  - **KakaoTalk**: `카카오톡으로 초대하기` calls `Kakao.Share.sendDefault` (feed template: title `<city> 여행에 초대합니다`, description, `content.link` and a `여행 참여하기` button, both pointing at the invite URL already shown in the modal so no popup is blocked by an await). The Kakao JS SDK 2.7.4 (~85 KB) is lazy-loaded by `loadKakao` with an SRI `integrity` hash (recompute it if the version changes), started when the invite modal opens so it is ready before the button is clicked; `initKakao` runs `Kakao.init(TripLogConfig.kakaoJsKey)`. It is not in `index.html`.
  - **Kakao settings**: `kakaoJsKey` is the Kakao app's "JavaScript 키", not the REST API key Supabase's Kakao login uses. It is public by design and protected by the domains registered in Kakao Developers: the site domain under the JavaScript key's SDK domains and under 제품 링크 관리 → 웹 도메인 (every origin used, e.g. `http://localhost:8080` and `https://triplog-nu.vercel.app`, and the shared link's domain). A missing registration shows Kakao's "요청 실패" page. `TripLogConfig.inviteImageUrl` is the card image, fetched by Kakao's servers, so it must be publicly reachable (`https://triplog-nu.vercel.app/img/invite-share.png`, a generated gradient placeholder in `triplog/img/`; it resolves only after deploying).
  - **Accepting** (`invitePage.js`, route `#/invite/:code`): calls `supabase.rpc('accept_trip_invite', { p_invite_code })` (001) instead of selecting `trip_invites` / inserting into `trip_members`, because an invitee is not a member yet and RLS forbids both. The function checks `expires_at`, inserts `(trip, me, 'editor')` with `on conflict (trip_id,user_id) do nothing` and returns the trip id. Then `storage.refreshTrips()` (so the schedule guard finds the trip), "여행에 참여했어요!" (or "이미 참여 중인 여행이에요" if the trip was already in the cache) + toast, and after 1.2 s `navigate('/schedule/:id', {replace:true})`. Error `invite_invalid_or_expired` (or a malformed code, checked client-side) shows "유효하지 않은 초대링크입니다"; other errors show a retry screen; a `runId` counter drops late results after leaving.
  - On the login page inside KakaoTalk's in-app browser a note says Google login may be blocked there (Google refuses embedded webviews) and suggests Kakao login.
