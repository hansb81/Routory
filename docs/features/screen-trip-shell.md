# Trip shell (SHELL)

> CLAUDE.md에서 이동된 상세 내용. 이 영역을 작업하기 전에 먼저 읽을 것.

- **Trip shell (SHELL, `tripShell.js`)**: the top icon bar (`MYTRIP-TOPBAR`), bottom tab bar (`MYTRIP-BOTTOMTABS`) and right slide-in menu (`MYTRIP-MENU`) used to belong only to the my-trip screen; they're now a single persistent DOM tree `tripShell.js` builds once and appends to `document.body` (like a modal), independent of the router's page-swapping. It shows itself (and toggles `body.has-trip-shell`) on `my-trip`/`schedule`/`budget`/`checklist`/`wallet`/`lodging` and hides on every other route (`router.onEnter` registered for every route name, including `notifications`/`settings`/`account-delete` — missing any of these from the list would leave the shell showing after navigating there from the drawer, since nothing else would ever re-run `updateShell` to hide it). Because it's `position: fixed` (both bars) rather than nested in one page's DOM, those fixed full-screen pages have to leave room for it: `my-trip`/`budget`/`checklist`/`wallet`/`lodging` use `top: var(--shell-top-h)` / `bottom: var(--shell-bottom-h)` instead of `inset: 0`; the schedule screen (still normal `body` scroll) instead gives `.app-top` a `margin-top`/sticky `top` of 60px (the bar's height *without* safe-area, since `:root`'s own safe-area padding already applies there — see **Mobile wrapper**'s safe-area note) and `.timeline` an extra 57px of bottom padding.
  - **Bottom tabs**: `일정`(→ `#/schedule/:id`) → `여행중`(→ `#/my-trip/:id`) → `여행지갑`(→ `#/wallet`) → `가계부`(→ `#/budget/:id`) → `체크리스트`(→ `#/checklist/:id`), five tabs. 여행지갑/가계부 used to be buttons in the schedule screen's own `QUICK-MENU` (`app.js#initQuickMenu`); they were pulled up into the SHELL's bottom tab bar instead, get their own new line icons (`ICONS.wallet`/`budget` in `tripShell.js`, a card/receipt pictograph respectively, same 24x24 `currentColor` style as the other tab icons), and each is active only on its own route (`activeOn: ["wallet"]`/`["budget"]`). Their own screens dropped the `←` back-to-schedule button too (getting back to schedule is what the `일정` tab is for now) — see the **Budget page** and **Wallet page** notes below. 체크리스트(`ICONS.checklist`, a checklist/clipboard pictograph) was added as a fifth tab next to 가계부 — see `screen-checklist.md`. 숙소 briefly got the same treatment (its own bottom tab, `#/lodging/:id`, with a bed icon) but was moved back to the schedule screen's `QUICK-MENU` next to 교통편 — so `일정`'s `activeOn` covers both `["schedule", "lodging"]` (숙소 has no tab of its own, so `일정` stands in for it while lodging is open) — see the **Schedule page** and **Lodging** notes below. The old dummy `저장`/`여행도구` tabs (toast-only, never implemented) were deleted outright, not replaced.
  - **Top bar**: a home icon (`ICONS.home`, `data-action="close"`, unchanged action/handler, still navigates to `#/main`) on the left, then a flexible spacer, then — mirroring `MAIN-HEAD`'s own "logo left, account right" layout — an account icon+name (`topbarAccountHtml()`, reusing `mainPage.js`'s `profileAvatarHtml` the same way the drawer's profile row does, sized like `.main-avatar`) right before ☰ (menu) on the right. The search and map icon buttons (and their "검색"/"지도" coming-soon toasts, `COMING_SOON` in `tripShell.js`) were removed outright, not just hidden — there was no screen behind either yet.
  - **Colors**: `.mytrip-bar`/`.mytrip-tabs`/`.mytrip-panel` (the slide-in menu) all use `--page-bg-blue` now, not their old `--mint`/`--surface`/`--surface` — see **Color policy: pastel**'s note below. The topbar's remaining icon buttons carry `.mytrip-icon-btn--dark` (previously only the drawer's own close button did) so they read as dark icons on the now-light bar instead of the old white-on-mint; `.mytrip-backdrop` (the dimmed area behind the open drawer) is unchanged.
  - **Right slide-in menu**: the panel head lost its "메뉴" text the same way MAIN-MENU did — it's now just 알림(🔔)/설정(⚙, the same shared `commonPages.js` icons and routes as MAIN-MENU) then 닫기(✕), right-aligned. Below the head, a profile row (`menuProfileHtml()`) was added, reusing `mainPage.js`'s `.main-menu-profile` CSS/markup verbatim rather than inventing a SHELL-specific version. Then the `<ul>` list: `여행 공유` (owner only, opens `invite.js`'s invite-link modal — moved here from the schedule page's old `#invite-row`; same owner-only rule since only `getTrip().role === "owner"` can read/insert `trip_invites` under RLS) then `여행 가져오기` (any role, whenever a trip is loaded; opens `tripImport.js`'s modal with `mode: "append", tripId`, same as the old `#invite-row`'s `📥 가져오기` button — see **Trip import**), then `동행자 관리` (any role, whenever a trip is loaded; calls `tripMembers.open(trip)` — no longer a dummy item; see **Members** for how the modal itself differs by role), then a red 여행 삭제 (owner, `trip.role === "owner"`) or a red 여행 나가기 (invited participant, both reading `storage.getTrip()` at open time) as the last item. 로그아웃 was removed from here too (not deleted from the app, just no longer shown in this menu) — `tripShell.js` no longer has a `logout()` function since nothing calls it any more.
  - **Delete / leave**: both close the menu and open one confirm dialog, `MYTRIP-EXIT-CONFIRM` (`EXIT_TEXT` holds the two texts; focus starts on 취소). Delete calls `storage.deleteTrip` (server `delete from trips`, children cascade, RLS owner only). Leave calls `storage.leaveTrip` (only my own `trip_members` row; needs the policy from 004, otherwise 0 rows and a message pointing to 004; the owner cannot leave; the leaver's items stay on the trip; they can rejoin with a valid invite). Both also remove this browser's photos for that trip's items, then go to `#/main` with a toast.
