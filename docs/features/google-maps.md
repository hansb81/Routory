# Google Maps

> CLAUDE.md에서 이동된 상세 내용. 이 영역을 작업하기 전에 먼저 읽을 것.

- **Google Maps** (`config.js`, `googleMaps.js`, `mapPicker.js`): every Google call goes through `googleMaps.js`: a lazy loader for the Maps JavaScript API (requested only the first time a map or lookup is needed) plus Geocoding, Places (New) and (since the my-trip status cards) Routes wrappers that return plain objects and Korean error messages (`errorMessage`). `searchNearby({center, radius, types, max})` (Places (New) Nearby Search, `rankPreference: POPULARITY`) predates the status cards — it originally backed lodging's now-removed nearby-pins feature — and is reused as-is by `myTripPage.js#hydrateNearbyCard`. It filters by `includedPrimaryTypes`, not `includedTypes` — confirmed live (raw REST call) that `includedTypes` matches a place's whole `types` array, so asking for `"restaurant"` also returns e.g. a department store whose food-court makes Google tag it with `restaurant` among a dozen other types, while its actual `primaryType` stays `department_store`; `includedPrimaryTypes` filters on that single dominant type instead and gives the expected result set. `travelDurationTo(origin, destination)` is new: `library("routes")` → `DistanceMatrixService`, driving mode, `destination` can be a plain address string (no coordinates needed) — used by `myTripPage.js#hydrateAirportTrafficCard`.
  - The key lives in `js/config.js` (`TripLogConfig.googleMapsApiKey`). It is visible in the page source, so it must be restricted by HTTP referrer and to Maps JavaScript / Geocoding / Places (New) / **Distance Matrix** in Google Cloud (Distance Matrix is new, added for `travelDurationTo` — an existing key needs this API turned on explicitly, it isn't covered by enabling Places (New)).
  - Every origin the app is opened from must be in the referrer list (`http://localhost:8080/*`, for a phone `http://<PC address>:8080/*`, and the deployed domain), otherwise the map fails with `RefererNotAllowedMapError` ("키 인증 실패" in the UI).
  - **The native Android app (`mobile/`) is a separate origin the referrer list must also cover.** Capacitor's default `server.hostname`/`androidScheme` (unset in `mobile/capacitor.config.json`, so Capacitor's own default applies) serves the WebView content from `https://localhost/`, not the `http://<PC address>:8080` origin the web build uses — so the same map key that works in a browser fails only inside the built app: the Maps script itself loads (that request isn't referrer-checked), but the auth check Google runs right after (on the first map/geocode/places call) sees `Referer: https://localhost/`, doesn't find it in the key's allowed list, and calls `gm_authFailure` — the map renders once, then turns gray with "키 인증 실패" (`googleMaps.js#errorMessage`'s `AUTH_FAILED` case), matching what actually happens on-device. Fix (dashboard, user's own step, same as the other referrer entries above): add `https://localhost/*` to the Google Maps key's HTTP referrer restrictions.
  - `mapPicker.js` draws the map and lets the user click the map (address via reverse geocoding) or a Google POI icon (name via place details), drag the marker, search (text search), and pick from popular nearby places. Responses are guarded with per-request counters so late replies can't overwrite newer ones.
