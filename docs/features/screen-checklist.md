# Checklist page (체크리스트)

> CLAUDE.md에서 이동된 상세 내용. 이 영역을 작업하기 전에 먼저 읽을 것.

- **Checklist page** (`checklistPage.js`, route `#/checklist/:id`; entered from the SHELL's bottom tab 체크리스트, 가계부 옆에 다섯 번째로 추가됨 — `tripShell.js`'s `MYTRIP-BOTTOMTABS`, `TABS` array): a full page (not a modal), same "fixed header + scrolling body" skeleton as **Budget page** (`.page[data-page="checklist"]` uses the same `top: var(--shell-top-h)` / `bottom: var(--shell-bottom-h)` positioning as `.page[data-page="budget"]`). Instead of grouping by Day, items are grouped by **category — a per-trip row the user controls**, not a fixed set. Shares the budget page's "share model" — any trip member (owner or editor) can see and edit every category/item, like `expenses` (005_budget.sql), not just their own.

- **배포 전 설계 변경 (2026-10-19)**: 처음엔 카테고리가 필수/의류/전자기기/세면·생활/상비용품 5개 고정값(DB check 제약으로 강제)이었다. 아직 한 번도 배포/실행되지 않은 상태에서 "카테고리를 할 일/준비물 2개 기본값으로 바꾸고, 사용자가 화면에서 자유롭게 추가·삭제할 수 있게 해달라"는 요청으로 전체를 다시 설계했다 — 새 마이그레이션을 쌓지 않고 `038_checklist.sql` 자체를 고쳤다(실제 데이터가 없는 상태라 안전했다; 자세한 이유는 `supabase/CLAUDE.md`의 038 항목 참고).

- **Data** (`storage.js`, `038_checklist.sql`): 두 테이블.
  - `checklist_categories` — `trip_id`별 카테고리 행. `label`(자유 텍스트, 1~20자, DB check), `sort_order`(그 여행 안에서만 의미 있는 나열 순서), `created_by`(처음부터 `on delete cascade`). RLS는 `expenses`와 같은 "멤버만 조회/수정" `for all`.
  - `checklist_items` — `category_id`가 `checklist_categories`를 **`on delete cascade`로 참조** — 카테고리를 지우면 그 안의 항목도 서버에서 함께 지워진다. `title`, `checked` boolean, `sort_order`(같은 `trip_id`+`category_id` 안에서만 의미 있음, `schedule_items.sort_order`·008과 같은 모양), `created_by`도 처음부터 cascade. RLS 동일.
  - `storage.js`가 노출하는 함수: 카테고리 쪽 `loadChecklistCategories`/`getChecklistCategories`(읽기, 캐시-후-새로고침 패턴)/`addChecklistCategory`/`deleteChecklistCategory`(쓰기 — 삭제는 서버 cascade로 항목도 지워지므로 `deleteChecklistCategory`가 클라이언트 캐시(`checklistCache`)에서도 그 `categoryId`의 항목을 같이 걷어낸다); 항목 쪽 `loadChecklistItems`/`getChecklistItems`(읽기)와 `addChecklistItem`/`updateChecklistItem`/`deleteChecklistItem`/`reorderChecklistItems`(쓰기, `category` 대신 `categoryId`를 받는다는 점만 예전과 다르다). `deleteTrip`도 두 캐시(+loaded/request 맵)를 같이 정리한다(이전엔 체크리스트 캐시 정리가 빠져 있던 기존 공백도 이번에 같이 고쳤다).

- **기본 카테고리 / 기본 항목 / 시딩** (`checklistCategoryData.js`#`DEFAULT_CHECKLIST_CATEGORIES`): 여행마다 처음 한 번만 까는 값 — "할 일"(여행자 보험 가입, 트래블 카드 신청, 호텔 찾기, 항공권 예약) / "준비물"(핸드폰 충전기, 여권, 보조배터리, 수영복, 상비약). `storage.js#ensureChecklistSeeded(tripId)`가 `checklist_seeds` 마커 테이블(`trip_id` 기본키, insert만 가능한 불변 마커)로 "이미 깔았는가"를 가린다 — 마커가 없으면 카테고리 2개를 먼저 insert하고(라벨로 되찾아 category_id를 연결 — insert가 여러 행의 반환 순서를 보장하지 않을 수 있어 index가 아니라 label로 매칭한다), 그 id로 기본 항목들을 insert한다. `checklistPage.js#render`는 이 여행의 **카테고리와 항목이 둘 다 0개**일 때만 `ensureChecklistSeeded`를 부른다 — 사용자가 전부 지워도(카테고리까지 다 지워도) 마커가 남아 있어 다시 깔리지 않는다. `checklistCategoryData.js`를 나중에 고쳐도 이미 시딩된 여행에는 영향 없다.

- **카테고리 추가** (요청: 우측 상단 + 버튼): `checklist-header-row`에 원형 파스텔 블루(`--accent`) "+" 버튼(`checklist-category-add-btn`, 클린 미니멀 베이스 팔레트의 데코용 아이콘 버튼 기본값) — 누르면 `CHECKLIST-ADD-CATEGORY` 모달(한 줄 입력, 20자 제한 — DB check와 맞춤)이 뜬다. `storage.addChecklistCategory({tripId, label})`은 그 여행의 캐시 기준 마지막 `sortOrder` + 1로 맨 끝에 붙인다. 새로 만든 카테고리는 `openState[category.id] = true`로 바로 열어서 보여준다.

- **카테고리 삭제** (요청: 좌로 스와이프 → "정말 삭제하시겠습니까?" 확인): 카테고리 헤더(`.checklist-category-header`)를 좌로 스와이프하면 카드 전체(`.checklist-category`, 헤더+본문)가 밀린다 — 끝까지 밀어도 항목과 달리 **바로 지우지 않고** `mainPage.js`의 여행 카드 스와이프 삭제와 같은 패턴으로 `CATEGORY_SWIPE_REVEAL_PX`(84px) 자리에서 멈춘 채 확인 모달(`CHECKLIST-CATEGORY-DELETE-CONFIRM`, "정말 삭제하시겠습니까?" + "그 안의 모든 항목이 함께 삭제돼요" 안내)을 띄운다. "취소"/Esc는 카드를 제자리로 되돌리고, "삭제"는 `storage.deleteChecklistCategory`를 호출해 카테고리와 그 안의 항목을 함께 지운 뒤 목록을 다시 그린다 — 삭제 중 실패하면 토스트만 띄우고 모달은 열어 둔다(재시도 가능).
  - 제스처 구현은 `checklistPage.js`의 단일 `gesture` 상태 객체에 `kind: "item"|"category"`를 추가해 항목 스와이프/드래그와 카테고리 스와이프를 같은 포인터 핸들러(`handlePointerDown/Move/Up/Cancel`)로 처리한다 — `kind:"category"`일 때만 `updateSwipe`가 즉시 지우는 대신 확인 모달을 띄우고(`gesture.confirming=true`로 추가 포인터 이동을 무시), `cleanup()`은 양쪽 모두 공통으로 포인터 캡처만 해제한다(카드의 보여진 위치는 그대로 유지 — 확인창이 그 위에 뜬다).

- **Category collapse/expand** (요청: 각각 열고 닫을 수 있고, 기본값은 맨 앞 카테고리만 열려 있다): `openState`는 `{ [categoryId]: boolean }` 모양으로, `checklistPage.js#render`가 그 여행의 카테고리 목록(`sortOrder` 순)을 받아올 때마다 맨 앞 카테고리만 `true`로 다시 세팅한다 — 그래서 페이지를 나갔다 들어오면 항상 "맨 앞만 열림"으로 리셋되지만, 화면이 열려 있는 동안의 토글/추가/삭제는 그대로 유지된다(add/delete/reorder 모두 `refreshVisible()`을 부르고, 이건 `openState`를 건드리지 않는다). 카테고리 헤더 클릭은 `commonPages.js`의 `toggleSection`/`sectionOpen`과 같은 "DOM에서 바로 `hidden` 속성 토글, 전체 재렌더링 없음" 방식.

- **항목 길이에 따른 줄바꿈** (요청: 체크리스트가 길어지면 줄바꿈, 사이즈 가변적): `.checklist-item-title`에서 `white-space: nowrap`/`text-overflow: ellipsis`를 걷어내고 기본 줄바꿈(`overflow-wrap: anywhere`만 안전망으로 추가)으로 바꿨다 — 제목이 길면 한 줄로 잘리지 않고 그만큼 그 항목의 `.checklist-item` 행 높이가 늘어난다. `body`의 전역 `word-break: keep-all`이 한글 단어가 음절 중간에서 끊기는 것을 막아준다.

- **Item row** (`.checklist-item-wrap` → `.checklist-item-delete-bg` + `.checklist-item`, mirrors `.budget-item-wrap`): a `<label>` wrapping a native checkbox (`accent-color: var(--accent)`, same pastel-blue convention as `.consent-checkbox-row input`) and the title — clicking anywhere in the row toggles the checkbox via normal label semantics; a `change` listener on the page calls `storage.updateChecklistItem(id, { checked })` then always re-renders from cache (success or failure, same "always re-render after" convention as the budget page's swipe-delete). Checked items get `.checklist-item--checked` (strikethrough + `--text-faint`, no new color role).

- **Swipe-to-delete (item)**: 좌로 스와이프하면 바로 지워진다(카테고리와 달리 확인창 없음 — 가벼운 되돌림 가능 동작). Same thresholds (`SWIPE_START_PX`, `SWIPE_DELETE_RATIO`), same animate-off-then-`deleteChecklistItem` sequence, same capture-phase `suppressNextClick` trick to stop the post-swipe synthetic click from toggling the checkbox underneath.

- **Drag-to-reorder** (요청: 항목 끝의 ≡ 손잡이로 드래그해서 순서 변경): `.checklist-item-handle` starts a drag immediately on pointerdown (no long-press), same `touch-action: none` + immediate `setPointerCapture` idea as `timelineDrag.js`'s drag handle. 한 카테고리(`category_id`) 안으로만 좁힌 단순 버전 — 카테고리를 넘나드는 이동, 자동 스크롤은 없다. On drop, `storage.reorderChecklistItems(orderedIds)` is called with the now-visible order within that one list. 카테고리 자체의 순서를 바꾸는 드래그는 없다(요청 범위 밖, 카테고리는 추가는 항상 맨 끝·삭제만 가능).

- **"+ 추가하기"** (per category, at the bottom of its body): opens a small shared modal (`CHECKLIST-ADD-ITEM`, one text input, 40-char max) rather than a full wizard. `addTargetCategoryId`(module-scope)가 어느 카테고리의 버튼을 눌렀는지 기억한다; submitting calls `storage.addChecklistItem({ tripId, categoryId, title })` (appended to the end of that category's `sort_order`) and re-renders. Closed/reset on `router.onLeave("checklist", ...)` alongside canceling any in-progress swipe/drag gesture and closing the add-category/category-delete-confirm overlays.

- **Routing/guards**: `#/checklist/:id` added next to `budget`/`wallet` everywhere those three are listed together — `router.js` (`ROUTES`, `PAGE_ALIASES`), `app.js` (`CONSENT_GATED`, `requireTrip` guard), `tripShell.js` (`SHELL_ROUTES`, `ALL_ROUTES`, `TABS`). No new icon file — `tripShell.js#ICONS.checklist` and `commonPages.js#HELP_ICONS.checklist` both inline the same clipboard-with-checkmarks path (same "copy the tab icon's path into the help icon" convention the other 4 tabs already follow).

- **Help page**: `commonPages.js`'s `HELP_SECTIONS` has a "체크리스트" entry (`help-checklist`) right after "가계부", matching tab order — covers opening/using the default list, collapsing categories, "+ 추가하기", 카테고리 추가/스와이프 삭제(확인창), swipe-delete, drag handle, and the "한 번 다 지우면 기본 항목이 다시 채워진다" gotcha from the seeding behavior above.
