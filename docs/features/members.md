# Members (멤버)

> CLAUDE.md에서 이동된 상세 내용. 이 영역을 작업하기 전에 먼저 읽을 것.

- **Members** (`tripMembers.js`; the avatar stack/`멤버 관리` row (`mount()`) is **currently unmounted** — see **My-trip page**, nothing calls `mount()` right now — but the management modal itself (`openManage`, exported as `open`) is mounted and reachable from the SHELL's right slide-in menu's `동행자 관리` item (`tripShell.js`, any role, see **Trip shell**)): overlapping round avatars (max 3, then `+N명`) of everyone in `trip_members`, and a modal listing members.
  - `openManage(trip)` (exported `open`) can be called by owner or editor alike — it no longer early-returns for non-owners. What differs is the content: `renderManage` reads `trip.role === "owner"` as `viewerIsOwner` and only then shows a `내보내기` button per non-owner, non-self member (first click turns it into `정말 내보내기`; the second runs `storage.removeMember` = `delete from trip_members where trip_id and user_id`; RLS: owner only, never self) — an invited editor instead sees a plain "함께하는 멤버" title/list with no 내보내기 button at all (and a different note line), matching the invite-side expectation that an invited member can see but not remove the people they're travelling with. `mount()`'s own avatar-stack button (`member-stack`, the `멤버 관리 ›` row) is still owner-only via `stackHtml(members, trip.role === "owner")` — but since nothing mounts it right now, every entry point to this modal today is the SHELL menu, open to both roles.
  - Names/avatars are not readable from the client (they live in `auth.users`), so `storage.loadMembers` calls the SQL function `get_trip_members(p_trip_id)` (003; security definer, members only, returns name + http(s) avatar, never email). Without 003 it falls back to plain `trip_members` (count only, my own name/photo from `auth.getProfile()`).
  - The modal is closed (`closeManage`) on leaving any SHELL route (`my-trip`/`schedule`/`budget`/`wallet`/`lodging`, matching `tripShell.js`'s `SHELL_ROUTES`) since it can now be opened from any of them, not just `my-trip`.
