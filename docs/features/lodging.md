# Lodging (숙소)

> CLAUDE.md에서 이동된 상세 내용. 이 영역을 작업하기 전에 먼저 읽을 것.

- **Lodging** (`lodgingData.js` lookup + `lodging.js` UI, route `#/lodging/:id`; entered from the schedule page's `QUICK-MENU`, 숙소 — `app.js#initQuickMenu` navigates to `#/lodging/:id` for the current trip, same as 교통편; it briefly had its own SHELL bottom tab instead but moved back here, see **Trip shell (SHELL)**'s "Bottom tabs" note): a full screen, not a modal (same `budgetPage.js`-style structure: SHELL stays visible — `lodging` is in `tripShell.js`'s `SHELL_ROUTES`/`ALL_ROUTES`, and counts toward the `일정` bottom tab like schedule itself does, since it has no dedicated tab of its own). The screen only has two sub-screens now (`state.page`: `map | dates`, not separate routes) — **map is the first/default screen** now (the old `list` sub-screen — a search box + a separate "지도에서 찾기" button + a "여행지 인기 숙소" list — was removed entirely, along with `lodgingData.js#searchLodging`/`fetchPopular`). The header's `←` only appears on `dates`, where it means "back to `map`" (`lodging.js#goTo` toggles the button's `hidden` attribute; `goBack()` always resolves to `goTo("map")`, since it can only ever be clicked from there); `map` itself has no back button (this is a holdover from when 숙소 was a SHELL tab — the `일정` tab still works as the way back to schedule from here, so it was left as-is rather than restoring a `←` on `map` too).
  - **map** (the only entry screen now, previously reached via a "지도에서 찾기" button from `list`): a search box on top, a Google map filling the rest below. The map **no longer pre-populates with nearby/popular lodging pins** — `lodgingData.js#nearbyLodgingPins` and the `idle`-triggered marker refresh in `lodging.js#ensureMapLoaded` were removed along with `list`; the map starts empty and only ever shows a marker for whatever was just searched and picked (`selectMapItem`, a single `mapState.adHocMarker` that gets replaced on each new pick — there's no more "highlight one of many pre-existing pins" case, so `clearSelection`/`selectMapItem` dropped the old `highlightedPin`/`pins` bookkeeping too). The search box (`findOnMap`) restricts to the `lodging` type first; only when that comes back empty does it fall back to plain geocoding the query so an address still resolves to a point (flagged `isAddressOnly`) — this is the deliberate exception for places like Airbnb listings that Google doesn't tag as `lodging`. Picking a search result (or getting a single auto-selected result) drops the marker and shows a confirm bar (`이 숙소 선택`); confirming is what proceeds to **dates**. The map instance itself is created lazily (only when this screen is first opened) and torn down implicitly on the next full page visit (the whole page `innerHTML` is rebuilt per router entry, same as `budgetPage.js`).
  - **dates**: unchanged check-in/check-out calendar limited to the trip range. Confirming saves an item on the check-in date with an extra `item.lodging` object (`checkIn/checkOut/nights/rating/ratingCount/placeId`; older items may have `stars` instead of `rating`) via `storage.addItem`, then navigates back to `#/schedule/:id` (which redraws the timeline from cache on its own `onEnter` hook — no separate `onChange` callback needed here). Clicking an existing lodging item on the timeline still opens the generic edit form (**SCHEDULE-FORM**, see above) with the date locked.
  - Places content must not be kept in localStorage (Google terms), so the one list left here (map search results) is cached in memory only, and it shows a "장소 정보: Google 지도" attribution (`.lodging-attribution`, hidden when the list is empty).
  - `.lodging-shell`'s background moved from `--page-bg` to `--surface-blue` (`#d6e4fb`) while this file was being touched (see **Color policy: pastel**'s note on `--surface-blue`) — `budgetPage.js`/`walletPage.js`'s own `-shell` backgrounds were left on `--page-bg` since those files weren't part of this pass. `.lodging-header` and `.lodging-map-search` (the search row above the map) are also `--surface-blue` now — same token as the shell behind them, on purpose (an earlier pass tried white for `.lodging-map-search` instead; that was superseded). Two buttons on this screen are `--dday-pastel-bg` instead of their generic class's usual color: the 검색 button (`.lodging-map-search .btn-save`) and "이 숙소 선택" (`.lodging-map-confirm .btn-save`) — both scoped narrowly so every other "저장"/submit button in the app (plain `.btn-save`, `--accent`) is unaffected.
