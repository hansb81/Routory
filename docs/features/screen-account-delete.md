# Account deletion (회원 탈퇴 / 계정 삭제 요청)

> CLAUDE.md에서 이동된 상세 내용. 이 영역을 작업하기 전에 먼저 읽을 것.

- **Account deletion (회원 탈퇴, `accountDeletePage.js`, route `#/account-delete`)**: opened only from Settings' 계정 section. Lists the same six data categories the privacy policy groups data into (계정 정보/여행 계획/일정/가계부/여행지갑 파일/초대·멤버 정보, wrapped in `.legal-content` — reusing `legalPages.js`'s paragraph/list spacing rather than new CSS) above a single confirm checkbox (`.consent-checkbox-row`, reused from the consent screen) that gates a `.btn-danger` "회원 탈퇴" button. Unlike `consentPage.js`'s checkbox state, this screen's `checked` flag is explicitly reset to `false` at the top of every `render()` call — a deliberate difference: the consent screen preserves state because leaving it only ever means "stepped out to read a policy, coming right back," while landing on this screen fresh should always demand a new confirmation. Clicking the button doesn't delete anything yet — it opens a second, separate confirm dialog (`ACCOUNT-DELETE-CONFIRM`, the same `.modal-overlay`/`.modal-confirm`/`.modal-actions-right` shape as `tripShell.js`'s `MYTRIP-EXIT-CONFIRM`) with 취소/탈퇴하기, matching this app's established "menu click, then a second real confirmation" pattern for irreversible actions (여행 삭제, 여행 나가기). Confirming calls the Edge Function `delete-account` (`supabase.functions.invoke`, no body — see **Edge Function `delete-account`** below for why the client can't do this itself); on success it `auth.signOut()`s (the server account is already gone, so the local session has to be cleared too), toasts, and navigates to `#/login`. **On any failure — network error or a specific server-side error alike — the dialog always shows the same fixed line, "탈퇴 처리 중 문제가 발생했습니다. 고객센터로 문의해주세요."**, never the function's actual (and more specific) error message; the real one only goes to `console.warn`. This is deliberate: the function's response names exactly which deletion step failed (useful in Edge Function logs), but that's not something to surface to an end user mid-account-deletion, so the client intentionally discards it in favor of one calm, consistent message. The button re-enables and the dialog stays open either way, so retrying is always one click away (every deletion step is a `WHERE ... = me` delete, safe to repeat). `router.onLeave("account-delete", ...)` hides the confirm overlay if the user navigates away mid-flow (same reasoning as `schedule.js`'s `closeAllOverlays`).


- **Account deletion request page (계정 삭제 요청, `triplog/account-deletion.html`, real path `/account-deletion`, not a hash route)**: a second, independent way to request account deletion, built specifically because Google Play's Data Safety form requires a URL where deletion can be requested **without logging in** — `#/account-delete` can't satisfy that (it's behind `requireLogin`). Structured exactly like `triplog/auth/naver-callback.html`: a standalone static file outside the SPA bundle (so it never loads `index.html`'s script chain or touches `router.js`'s guards at all — "no login required" isn't a route exception here, it's structurally true), with its own inline `<style>` (hex colors copied from the design tokens by hand, same as `naver-callback.html` — see that file's note and CLAUDE.md's **Font color policy**) and its own ad-hoc `supabase-js` client (same CDN script tag, same project URL/anon key, `persistSession: false` since this page never needs a session — it only ever fires one write and is done). `vercel.json`/`serve.py` route the clean URL to this file the same way they do for the Naver callback (see **Commands**).
  - The form (email required, login-method dropdown optional, free-text message optional) inserts one row into `account_deletion_requests` (`012_account_deletion_requests.sql`) directly via the anon key — no Edge Function involved for this path. That's deliberate, not a shortcut: the table's RLS only allows `insert`, so there's nothing sensitive an attacker could do by hitting it directly, and routing it through a function would add nothing. Actually deleting the account from a submitted request is **explicitly a manual step for now** (an operator reads the table from the Supabase dashboard) — wiring it to call the `delete-account` Edge Function automatically wasn't asked for and wasn't built; doing so later isn't straightforward anyway, since that function authenticates the caller via their own session JWT (see **Edge Function `delete-account`**), which a signed-out visitor on this page never has.
  - A `.self-serve-note` box at the top links to `#/login` and tells anyone who *can* still log in to use the faster in-app flow (**Account deletion (회원 탈퇴)**) instead — this page is the fallback for people who can't or won't log in, not the primary path.
  - On submit failure (including "migration 012 not run yet," `PGRST205`, verified live the same way **Edge Function `delete-account`** was) the page shows one fixed line regardless of cause — "요청을 보내지 못했어요. 잠시 후 다시 시도해주시거나, 다른 방법으로 문의해주세요." — the same "don't surface internals, console.warn instead" principle used everywhere else failure messages were specified in this app.
