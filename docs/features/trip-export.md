# Trip export (여행 내보내기)

> CLAUDE.md에서 이동된 상세 내용. 이 영역을 작업하기 전에 먼저 읽을 것.

- **Trip export (여행 내보내기, `tripExport.js`, a modal opened from 설정(`#/settings`)'s "여행 내보내기" item, not a route)**: the inverse of trip import — picks one existing trip and writes its 일정(`schedule_items`)/가계부(`expenses`) out to a two-sheet `.xlsx` file (sheets "일정"/"가계부"). Nothing else (photos, 여행지갑 files, members) is exported, per spec ("일정과 가계부만 내보내기 할 수 있다"). Two `document.body`-appended overlays, same `accountDeletePage.js`-style dynamic-DOM pattern (no static markup in `index.html`):
  - **여행 고르기** (`.pick-list`, the same `.pick-item`/`.pick-info`/`.pick-name`/`.pick-sub`/`.pick-btn` classes `tripSetup.js`'s city list uses): `open()` shows a loading line, awaits `storage.refreshTrips()`, then lists every trip from `storage.getAllTrips()` with a short period subtitle. Picking one's "내보내기" button opens the confirm overlay on top of it (left showing underneath, same "later-appended element wins the paint order" trick `aiNotice.js` uses, rather than hiding/re-showing the list).
  - **확인창** ("선택한 여행을 내보내시겠어요?", the same `.modal-confirm` shape as `tripShell.js`'s `MYTRIP-EXIT-CONFIRM`/`accountDeletePage.js`'s delete confirm): confirming awaits `storage.loadItems`/`loadExpenses` for that trip, lazy-loads SheetJS (`xlsx`, see below), builds the workbook, and saves it. On failure the dialog stays open with a `.form-error` line (same "don't lose the selection" convention as every other form); on success both overlays close and a toast confirms.
  - **엑셀 생성**: SheetJS is lazy-loaded from jsDelivr (`xlsx@0.18.5/dist/xlsx.full.min.js`) the same way `invite.js#loadKakao` lazy-loads the Kakao SDK — integrity hash, loaded once on first use, never for visits that don't open this modal. Row-building deliberately reuses existing display logic rather than re-deriving it: the 일정 sheet's title/time/category columns mirror `app.js#renderItemCard`'s own place→title→memo fallback and flight/lodging icon logic (including calling `flight.js`'s exported `summary(item)` for flight rows, the same string the timeline card shows), and the 가계부 sheet's category/payment labels come from `expenseCategoryData.getCategoryByKey`/a small cash↔card map. Rows are sorted chronologically (일정 by `date` then `sortOrder`; 가계부 by `dayKey` with `"prep"` sorting first).
  - **저장 위치 (PC vs 모바일)**: `saveWorkbook` tries `window.showSaveFilePicker` (the File System Access API) first — on supporting desktop browsers (Chrome/Edge) this pops the OS's real "다른 이름으로 저장" dialog, satisfying the PC requirement ("저장위치 선택필요"); a user-cancelled picker (`AbortError`) is rethrown and the caller treats it as "nothing happened" (no error shown, confirm dialog just re-enables) rather than a failure. Any browser without that API — every mobile browser, and also a native Capacitor WebView, which doesn't implement it either — falls through to a plain `<a download>` click, which hands off to the browser's own "다운로드"/"파일에 저장" flow (satisfies the mobile requirement without this app building any file-picker UI of its own). No native Capacitor filesystem plugin (`@capacitor/filesystem`) was added for this — that would need a new `mobile/package.json` dependency and `npx cap sync`, a larger change than this feature asked for; the web download fallback already covers the native WebView case.
  - Verified end to end in a real signed-in browser session against real trip data (read-only — nothing is written back to Supabase): opened the picker, triggered the real `showSaveFilePicker` dialog and confirmed cancelling it leaves the confirm dialog usable again, then forced the `<a download>` fallback path and parsed the resulting blob back through `XLSX.read` to confirm both sheets' headers and rows match the trip's actual schedule/expense data.
