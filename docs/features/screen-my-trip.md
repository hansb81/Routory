# My-trip page

> CLAUDE.md에서 이동된 상세 내용. 이 영역을 작업하기 전에 먼저 읽을 것.

- **My-trip page** (`myTripPage.js`, route `#/my-trip/:id`, the SHELL's `여행중` tab): the space between the SHELL's two bars is filled with a `computeTripPhase(trip, items, options)` state classifier plus a card layout built on top of it — no more "준비 중이에요." placeholder. The screen used to hold a different, now-removed header/category-list/추천-card design (destination/D-day/dates header, category tab bar, a "추천" card list with a Day-picker, participant-avatar row); none of that survived the SHELL extraction, and the current card screen was built independently afterward.
  - **`computeTripPhase`** (exported as `window.TripLog.myTripPage.{PHASE, computeTripPhase}`) compares now against `trip.startDate`/`endDate` and the trip's `schedule_items` to return one of three phases: `BEFORE_TRIP` (today < startDate), `BEFORE_DEPARTURE` (today === startDate, a `category:"flight"` item exists, and more than `PRE_DEPARTURE_BUFFER_MIN` — 3 hours — remain until its `depTime`; no flight that day skips straight to the next phase), or `IN_TRIP` (everything else — the cutover to "in trip" happens 3 hours *before* departure, not at departure itself, along with `nextItem`: the earliest today-dated item whose time hasn't passed, using `item.flight.depTime` → `item.time` → a configurable default time, `"09:00"`, in that order). `options.now`/`options.defaultTime` make it independently testable.
  - **Cards**: `render()` builds a fixed header (phase title + a phase-specific subtitle: D-day / "출발까지 N 남았어요" / next-item place) and a `.mytrip-status-scroll` of cards stacked vertically (never a grid, to match the other SHELL screens' side margins via `var(--space-5)`) — `buildCards(trip, result)` picks the set per phase, ordered most-urgent-first: `BEFORE_TRIP` → 환율/날씨/시차(국내 여행은 skip)/현지 뉴스/할인 정보; `BEFORE_DEPARTURE` → 공항 이동 교통상황 then, only when the departure airport is in `CONGESTION_AVAILABLE_AIRPORTS`, 공항 혼잡도; `IN_TRIP` → one "다음 일정 장소 주변" card (shows an empty-state message when `nextItem` is null). Each card shows a small "오후 3시 기준"-style timestamp (`formatTimeLabel`). A manual 새로고침 button (top-right) re-runs the same render path against `new Date()`, independent of any future auto-refresh — every render call bumps `el.dataset.statusGen` so a slow async card update from a superseded render can detect it's stale and no-op instead of clobbering newer content.
  - **Real API cards, graceful-degradation group** (the `BEFORE_TRIP` phase's cards; each card is first painted with a loading placeholder synchronously, then a `hydrate*Card` async function fills in the real body — see the "실시간 연동" comment block in `myTripPage.js` for the full rationale). On failure these show an in-card failure message (or a stale-cache fallback), never hiding the card — unlike the next group:
    - **환율** (`hydrateExchangeCard`): `open.er-api.com/v6/latest/<currency code>` (free, no key, daily-refresh) for the trip destination's currency → KRW rate. **국내 여행(`isDomesticTrip(trip)`)이면 환전이 필요 없어 카드 자체를 지운다** — `trip.destinationId`가 있으면 국내일 수 없으므로 바로 `false`, 없으면 `trip.cityId`로 `destinations.js`의 `region`을(국내 도시는 `region:"domestic"`), `cityId`도 없으면(옛 방식으로 직접 입력) `destination` 문자열의 나라 이름이 `"대한민국"`인지로 판단한다 — 시차 카드(아래)도 이 같은 함수를 공유한다. 해외 여행이면 **PRD v12 이후 분기**: `trip.destinationId`가 있으면(여행지 선택 화면에서 search-destination의 select로 확정된 여행) `trip.currency`(ISO 코드, `018_trips_destination_fields.sql`)를 그대로 쓴다 — 통화 이름은 있으면 `currencyData.findByCode`로, 없으면(13개 큐레이션 표 밖) 코드 자체를 보여준다; `trip.currency`가 `null`이면(나라 자체를 모름, `country_currency`에 없음 — `015` 참고) **카드를 통째로 지운다**(`.mytrip-card[data-card="exchange"]`를 `.remove()` — 틀린 통화를 보여주는 대신). `destinationId`가 없으면(옛 방식 해외 여행) 예전 그대로 `destination` 문자열의 나라 이름을 `currencyData.findByCountry`로 찾고, 못 찾으면 USD로 대체. **표시 단위(`exchangeDisplayUnit`)**: 1단위당 원화가 1원도 안 되는 통화(VND·IDR 등)는 "1 동 = ₩0"처럼 보여줄 게 없어지므로, 한국 기준 1원 이상이 되는 10의 거듭제곱 단위(1 → 10 → 100 → ...)로 올려서 보여준다(예: "100 동(VND) = ₩5.4"). USD·JPY처럼 1단위가 이미 1원을 넘는 통화는 그대로 1단위를 쓴다. 성공 응답은 `localStorage["triplog.exchangeRate.<code>"]`에 `{rate, fetchedAt}`로(단위 적용 전의 1단위 원가로) 캐시하고, 실패하면 그 캐시로 "갱신 실패, <fetchedAt> 기준"을(캐시된 rate에도 같은 단위 규칙을 적용), 캐시도 없으면 실패 문구를 보여준다 — 이 캐싱/실패 처리는 두 분기 모두 공통이다.
    - **날씨** (`hydrateWeatherCard`): **PRD v12 이후**: `trip.lat`/`trip.lng`가 있으면(destinationId 확정 여행) 그 좌표를 바로 쓴다(`geocodeCity`가 지오코딩을 건너뛴다) — 매번 이름으로 다시 찾지 않고, 동명이인 도시로 잘못 짚을 위험도 없다. 없으면(국내·옛 방식) 예전 그대로 Open-Meteo의 무료 지오코딩으로 도시 이름(`trip.cityId`가 있으면 `destinations.js` 도시의 영문 위키 제목, 없으면 `destination` 문자열의 도시 부분)을 찾는다. 이후 일별 예보(weathercode + min/max)는 여행 날짜 범위를 Open-Meteo 무료 한도(~16일)로 자르고, 16일 넘는 날은 "아직 예보 범위 밖이에요"로 대신한다. 7일 넘는 날이 하나라도 보이면 "장기 예보 참고용 · 7일 이후 예보는 정확도가 낮아요"를 덧붙인다.
    - **시차** (`hydrateTimezoneCard`, key `timezone`): 날씨 카드 바로 밑의 **독립된 카드** — 날씨 본문에 줄을 더 붙이는 게 아니라 `buildCards`가 별도 카드 객체를 하나 더 만든다. 국내 여행이면 `isDomesticTrip`로 `buildCards` 단계에서 애초에 만들지 않는다(네트워크 호출도 없음). 좌표 조회는 날씨 카드와 같은 `geocodeCity(trip)`를 그대로 쓰지만(날씨 fetch와는 독립적으로 각자 부른다 — 날씨 예보가 16일 범위를 벗어나 실패해도 시차는 영향받지 않아야 하므로), **시차 계산 자체는 추가 API 호출이 없다**: `geocodeCity`가 돌려주는 IANA 시간대 이름(`trip.timezone` 그대로, 또는 옛 방식이면 Open-Meteo Geocoding 응답의 `timezone` 필드)을 `Intl.DateTimeFormat`으로 직접 포맷해서(`resolveTimezoneInfo` — "그 시간대로 포맷한 값을 UTC로 재해석해 원래 시각과 비교"하는 표준 트릭) 지금 이 순간의 UTC 오프셋과 현지 시·분을 구한다. `timeDiffLabel`이 한국(KST, UTC+9, DST 없음) 기준으로 "한국보다 N시간 빨라요/늦어요"/"한국과 시차가 없어요"를 만들고(인도처럼 30분 단위 시차도 소수로 보인다), `clockLabel`이 보조 줄에 "현지 시각 오후 3시 20분"을 더한다. 시간대 이름 자체를 못 구하면(아주 드묾) 다른 카드들과 같은 실패 문구를 보여준다(카드를 숨기지 않음 — graceful-degradation group).
    - **현지 뉴스 / 할인 정보** (`hydrateBriefingCards`, one function feeding both cards from a single call since they share one response): calls the Supabase Edge Function `travel-briefing` (`supabase/functions/travel-briefing/index.ts`, see **Server** below) with `{destination, startDate, endDate}` and renders `data.news`/`data.deals` as `title`/`summary`/an out-linking `sourceUrl` per item (`briefingItemHtml`, styled `.mytrip-briefing-*`); every item is guaranteed to have a source link (the function itself drops sourceless items) so the card never renders text without attribution. `data.stale: true` (the function fell back to a >24h-old cache because a fresh fetch failed) adds a small "갱신 실패 · 이전에 가져온 정보예요" note under the list; a request-level failure (no cache at all) shows a plain failure message per card instead.
  - **Real API cards, hide-on-failure group** (the `BEFORE_DEPARTURE` phase's two cards plus `IN_TRIP`'s one card; same loading-placeholder-then-hydrate pattern, but any failure removes the card element outright via `body.closest(".mytrip-card").remove()` instead of showing a message — this was an explicit requirement for these three, not a stylistic choice):
    - **공항 이동 교통상황** (`hydrateAirportTrafficCard`): calls `navigator.geolocation.getCurrentPosition` (`getCurrentPosition`, wrapped in a Promise; this is also what triggers the browser's location-permission prompt) and, on success, `googleMaps.travelDurationTo(pos, airport.name)` (new — `googleMaps.js`, uses the Maps JavaScript API's `routes` library / `DistanceMatrixService`, driving mode, destination passed as the plain airport name string rather than needing stored coordinates). No geolocation support, a denied/failed permission prompt, or no route found all reject the same way, which the `catch` turns into removing the card. **Requires the Distance Matrix API to be enabled** for the existing Google Maps key (config.js's top comment lists it now) — this is a new requirement beyond the Maps JavaScript/Geocoding/Places (New) already documented.
    - **공항 혼잡도** (`hydrateAirportCongestionCard`): only even attempted when `buildCards` finds the departure airport in `CONGESTION_AVAILABLE_AIRPORTS` (currently just `Set(["ICN"])` — every other domestic airport and all foreign ones never get this card built in the first place, satisfying "해외 공항은 항상 숨김" by construction); calls the Edge Function `airport-congestion` (see **Server**) and removes the card on any non-`available:true` response. **The Incheon Airport public-data integration itself is unverified** — see that function's own doc comment/README for why (data.go.kr gates the real endpoint spec behind an approved application) and what was done to make an unverified guess safe to ship (it no-ops to `available:false` — i.e. the card just stays hidden — until both of its secrets are set).
    - **주변 맛집/볼거리** (`hydrateNearbyCard`, only when a phase-3 `nextItem` exists): reuses `googleMaps.js#searchNearby` (Places API (New) Nearby Search — the "기존에 만들어둔 추천카드 로직" this was asked to reuse; it already existed for lodging's now-removed nearby-pins feature and needed no changes) with `center` = the next item's own `lat`/`lng`, a 1 km radius, and `types: ["restaurant", "cafe", "tourist_attraction"]`. **PRD v12(여행지 확장) 점검 결과**: 이 카드는 트립의 목적지(`destinationId`/`trip.lat`/`trip.lng`)를 전혀 쓰지 않는다 — 항상 그날 일정 항목 자체의 좌표만 본다. 그래서 여행지 선택 체계가 바뀌어도 이 카드는 영향이 없다(고칠 것이 없었다). Distances shown per spot reuse `util.js#haversineKm` (already shared with `dayMap.js`/`app.js`) formatted by a small local `formatDistanceKm` (a deliberate copy of `app.js`'s own formatting rule, to avoid adding a cross-module dependency for one string helper). Unlike the other two cards in this group, a missing `nextItem.lat`/`lng` (a plain item typed in without ever touching the map picker) shows an in-card message instead of hiding — only a `nextItem` being null at all (nothing left to do today) or a `searchNearby` failure hide/message per the existing empty-state convention; this one was **not** asked to hide on failure the way the other two were, so it keeps the graceful-degradation style.
  - `myTripData.js` now only exports `CATEGORY_META` (still used by `tripImportPreview.js`); the dummy `CATEGORIES`/`getCategoryItems`/`getRecommendations` data went with the removed content.
  - **Members avatars are currently unmounted**: `tripMembers.js` (avatar row + "멤버 관리" modal) was only ever mounted by my-trip's old header into a `[data-members]` container that no longer exists, so `tripMembers.mount()` is never called and that feature has no entry point right now (the module, its CSS and the server function `get_trip_members` are all still there, just unreachable from the UI — re-mount it somewhere, e.g. the schedule header, to bring it back).
