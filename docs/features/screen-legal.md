# Legal pages (이용약관 · 개인정보처리방침)

> CLAUDE.md에서 이동된 상세 내용. 이 영역을 작업하기 전에 먼저 읽을 것.

- **Legal pages (이용약관 · 개인정보처리방침, `legalPages.js`, routes `#/terms`/`#/privacy`)**: static draft text for the terms of service and privacy policy, reusing `commonPages.js`'s `.simple-page-header`/`←` pattern for the header but with real scrollable body content (`.legal-content`, new CSS: `h2`/`p`/`ul` spacing) instead of a placeholder. **Not gated behind login** (`app.js`'s `requireLogin` list does not include `terms`/`privacy`) — a signed-out visitor has to be able to read these before agreeing to anything. Content is organized as plain JS data (`TERMS_SECTIONS`/`PRIVACY_SECTIONS`, each `{ h, p?, ul? }`) rendered through one `sectionHtml()` function, not hand-written HTML per section, so adding/editing a clause is a data change. The privacy policy's data-category list (회원정보/여행정보/항공권정보/가계부정보/여행지갑 파일/초대·공유정보) was written to match what the app actually stores per `storage.js`/`walletForm.js`/the Edge Functions (e.g. explicitly noting ticket photos are sent to Gemini for OCR but never persisted, and that wallet files sit in a private Storage bucket) rather than generic boilerplate. **This text is still not a lawyer-reviewed document** — the file's own top comment says so — but as of the Google Play prep pass below it's no longer a visible "초안/미구현" placeholder either; this is independent of the version number (see next bullet). `legalPages.js` loads right after `commonPages.js` (needs `router`/`util.escapeHtml`, both already loaded by then) and exports `TERMS_VERSION`/`PRIVACY_VERSION` as `window.TripLog.legalPages` so `consentPage.js` writes the exact same string it displays.
  - **PRD v11 push notifications**: 섹션 1(수집 항목)에 "푸시 알림 토큰(기기 식별 정보)", 섹션 3(이용 목적)에 알림 발송, 섹션 4(보유 기간)에 토큰 삭제 시점(알림 끄기/로그아웃/탈퇴), 섹션 6(처리위탁)에 "Firebase Cloud Messaging(Google)"을 추가했다 — `docs/data-safety.md`(Google Play Data Safety 설문 정리본)와 항목을 맞춰 뒀으니 둘 중 하나를 고치면 다른 쪽도 같이 봐야 한다. `PRIVACY_VERSION`을 `"1.0"→"1.1"`로 올렸지만, **버전 번호를 올리는 것과 기존 동의자에게 실제로 재동의를 받는 것은 다른 일**이다 — `storage.js#hasConsent()`는 `user_consents` 행이 "존재하는지"만 보고 그 행의 `privacy_version`이 지금의 `PRIVACY_VERSION`과 같은지는 비교하지 않는다, 즉 버전 비교로 재동의를 강제하는 로직이 아직 없다(이번 작업 범위 밖이라 손대지 않았다 — 필요해지면 `requireConsent`가 `storage.getConsent()?.privacyVersion !== PRIVACY_VERSION`도 같이 봐야 한다).
  - **2026-10-18 Google Play 등록 준비 패스** (`TERMS_VERSION` `"1.0"→"1.1"`, `PRIVACY_VERSION` `"1.1"→"1.2"`, 사용자가 `AskUserQuestion`으로 직접 확정한 값들): 제8조/섹션4/섹션7의 "탈퇴 기능 미구현"/"설정에서 처리 불가" 문구를 지웠다 — `accountDeletePage.js`(`#/account-delete`)와 로그인 없는 `/account-deletion` 페이지가 이미 구현돼 있어서(**Account deletion** 문서 참고) 더 이상 사실이 아니었다. `render()`의 메타 줄도 "초안(draft) — 아직 시행되지 않았어요"에서 `버전 X · ${EFFECTIVE_DATE} 시행`으로 바뀌었다(`EFFECTIVE_DATE = "2026년 10월 18일"`, 상수 하나로 관리). 섹션6(처리위탁)에 Resend(1:1 문의 메일 발송, `contactForm.js`/`send-contact-email`)와 AviationStack(회원 개인 API 키로 직접 조회하는 항공편 정보 — 서버가 아니라 브라우저에서 바로 나가는 호출이라 "처리위탁"과는 성격이 다르지만 투명성을 위해 같이 적었다)을 추가했다. 섹션10 개인정보 보호책임자 연락처를 placeholder(`privacy@example.com`)에서 실제 값(`lorddark01@gmail.com`, Routory 운영자 표기)으로 교체했다.
  - **새 페이지: AI 및 외부 서비스 이용 안내 (`#/ai-usage`, 같은 `legalPages.js` 파일)**: 개인정보처리방침 섹션 6을 "무엇을·왜·어디서(출처 URL)" 기준으로 더 자세히 풀어 쓴 별도 목록 페이지 — Gemini/Maps/FCM/Web Push/Supabase/소셜로그인/카카오 SDK/AviationStack/Resend/공공데이터 API, 오픈소스 라이브러리(SheetJS), 관리자 전용 API(Pexels, `search-pexels` Edge Function)까지 전부 나열한다. `render()`를 `(title, sections, metaText)` 시그니처로 바꿔(기존엔 `version`을 받아 "버전 X · 초안..." 문자열을 직접 조립했다) terms/privacy는 `버전 X · 시행일` 문자열을, 이 페이지는 버전 개념이 없어 `최종 업데이트 ${LAST_UPDATED}` 문자열을 넘긴다. 동의 대상 문서가 아니라서 `consentPage.js`/`010_user_consents.sql`과는 무관하고, `router.js`(ROUTES/PAGE_ALIASES)·`tripShell.js`(`ALL_ROUTES`)·`commonPages.js`(설정 > "개인정보 및 약관" 섹션의 네 번째 항목, `data-action="ai-usage"`)에 terms/privacy와 나란히 등록돼 있다 — 로그인 가드 없음(`app.js`의 `CONSENT_GATED`에 포함 안 함), terms/privacy와 동일한 이유.
