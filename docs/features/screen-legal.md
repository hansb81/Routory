# Legal pages (이용약관 · 개인정보처리방침)

> CLAUDE.md에서 이동된 상세 내용. 이 영역을 작업하기 전에 먼저 읽을 것.

- **Legal pages (이용약관 · 개인정보처리방침, `legalPages.js`, routes `#/terms`/`#/privacy`)**: static draft text for the terms of service and privacy policy, reusing `commonPages.js`'s `.simple-page-header`/`←` pattern for the header but with real scrollable body content (`.legal-content`, new CSS: `h2`/`p`/`ul` spacing) instead of a placeholder. **Not gated behind login** (`app.js`'s `requireLogin` list does not include `terms`/`privacy`) — a signed-out visitor has to be able to read these before agreeing to anything. Content is organized as plain JS data (`TERMS_SECTIONS`/`PRIVACY_SECTIONS`, each `{ h, p?, ul? }`) rendered through one `sectionHtml()` function, not hand-written HTML per section, so adding/editing a clause is a data change. The privacy policy's data-category list (회원정보/여행정보/항공권정보/가계부정보/여행지갑 파일/초대·공유정보) was written to match what the app actually stores per `storage.js`/`walletForm.js`/the Edge Functions (e.g. explicitly noting ticket photos are sent to Gemini for OCR but never persisted, and that wallet files sit in a private Storage bucket) rather than generic boilerplate. **This text is an explicit, code-commented draft, not legal advice** — the file's own top comment says so prominently, since nothing here has had a lawyer's review; this is independent of the version number (see next bullet). `legalPages.js` loads right after `commonPages.js` (needs `router`/`util.escapeHtml`, both already loaded by then) and exports `TERMS_VERSION`/`PRIVACY_VERSION` (`"1.1"` as of PRD v11's push notification data item below — was `"1.0"`) as `window.TripLog.legalPages` so `consentPage.js` writes the exact same string it displays.
  - **PRD v11 push notifications**: 섹션 1(수집 항목)에 "푸시 알림 토큰(기기 식별 정보)", 섹션 3(이용 목적)에 알림 발송, 섹션 4(보유 기간)에 토큰 삭제 시점(알림 끄기/로그아웃/탈퇴), 섹션 6(처리위탁)에 "Firebase Cloud Messaging(Google)"을 추가했다 — `docs/data-safety.md`(Google Play Data Safety 설문 정리본)와 항목을 맞춰 뒀으니 둘 중 하나를 고치면 다른 쪽도 같이 봐야 한다. `PRIVACY_VERSION`을 `"1.0"→"1.1"`로 올렸지만, **버전 번호를 올리는 것과 기존 동의자에게 실제로 재동의를 받는 것은 다른 일**이다 — `storage.js#hasConsent()`는 `user_consents` 행이 "존재하는지"만 보고 그 행의 `privacy_version`이 지금의 `PRIVACY_VERSION`과 같은지는 비교하지 않는다, 즉 버전 비교로 재동의를 강제하는 로직이 아직 없다(이번 작업 범위 밖이라 손대지 않았다 — 필요해지면 `requireConsent`가 `storage.getConsent()?.privacyVersion !== PRIVACY_VERSION`도 같이 봐야 한다).
