# PRD v12 - 여행지 확장·도시 검색

> Routory 여행지 선택 화면에 지역 탭을 늘리고, 프리셋에 없는 나라·도시도 검색으로 추가할 수 있게 한다.

## 1. 배경과 목표

- 현재 여행지 선택은 일본 / 동남아 / 중국 탭의 프리셋 목록만 지원하고, 목록에 없는 곳은 검색되지 않는다.
- 목표 1: 지역 탭을 10개로 확장한다.
- 목표 2: 프리셋에 없더라도 나라·도시 이름(해외·국내 모두)을 입력하면 관련 도시가 검색 결과로 나온다.

## 2. 지역 탭 구성

| 탭 | 대표 도시(프리셋 예시) |
| --- | --- |
| 일본 (기존) | 도쿄, 오사카, 교토, 후쿠오카, 삿포로, 오키나와 |
| 동남아 (기존) | 방콕, 다낭, 하노이, 싱가포르, 세부, 발리, 코타키나발루 |
| 중국 (기존) | 상하이, 베이징, 칭다오, 청두, 홍콩, 마카오 |
| 대만 (신규) | 타이베이, 타이중, 가오슝, 타이난, 화롄 |
| 북미 (신규) | 뉴욕, LA, 샌프란시스코, 라스베이거스, 하와이, 밴쿠버, 토론토 |
| 중미·카리브 (신규) | 칸쿤, 멕시코시티, 하바나, 푼타카나, 파나마시티, 산호세(코스타리카) |
| 남미 (신규) | 리우데자네이루, 부에노스아이레스, 리마, 쿠스코, 산티아고, 보고타 |
| 오세아니아 (신규) | 시드니, 멜버른, 브리즈번, 골드코스트, 오클랜드, 퀸스타운, 괌, 사이판 |
| 유럽 (신규) | 파리, 런던, 로마, 바르셀로나, 프라하, 스위스(취리히·인터라켄), 비엔나 |
| 중东 (신규) | 두바이, 아부다비, 이스탄불, 도하, 텔아비브, 카이로 |

- 프리셋 목록은 코드 상수가 아니라 DB 테이블(`destinations`)로 두어 앱 배포 없이 추가·수정할 수 있게 한다.
- 탭 순서는 사용자 이용 빈도 기준으로 일본, 동남아, 중국, 대만, 유럽, 북미, 오세아니아, 중동, 중미·카리브, 남미로 한다. 국내 여행은 별도 '국내' 탭으로 두는 것을 제안한다 (확인 필요).
- 하와이·괌·사이판처럼 지역 경계가 애매한 곳은 한 곳에만 두고, 검색으로 어느 탭에서든 찾을 수 있게 한다.

## 3. 자유 검색

### 3-1. 사용자 동작

1. 검색창에 '프라하', 'Prague', '체코', '제주', '미국' 등을 입력한다.
2. 입력 중(0.3초 디바운스) 후보 목록이 나온다. 한국어·영어 모두 지원한다.
3. 나라 이름을 입력하면 해당 나라의 대표 도시가 나온다 (예: '체코' → 프라하, 체스키크룸로프, 브르노).
4. 도시를 누르면 여행 만들기 화면의 여행지로 들어간다.
5. 결과 상단에는 내 프리셋에 있는 곳, 그다음 외부 검색 결과 순으로 보여준다.

### 3-2. 검색 소스 (결정 필요)

| 방식 | 장점 | 단점 |
| --- | --- | --- |
| A. Google Places Autocomplete (New) | 이미 쓰는 Google Places와 키·정산이 같다. 한국어 지원, 도시·국가 타입 필터, 결과 품질이 좋다 | 호출량에 따라 과금. 요금·무료 한도는 구현 전에 공식 문서로 확인 필요 |
| B. Open-Meteo Geocoding API | 키 없이 무료, 한국어 지원, 응답에 위도·경도·국가코드·시간대가 함께 온다 | 도시 단위 위주라 나라 이름 검색의 품질이 약할 수 있고, 상업 이용 조건 확인 필요 |
|  |  |  |

- 제안: A를 메인으로, 실패·한도 초과 시 B로 폴백한다. 둘 다 정확한 한도·요금·파라미터는 이 문서 작성 시점에 확인하지 못했으므로 구현 첫 단계에서 공식 문서로 검증한다.
- API 키는 클라이언트에 두지 않고 Edge Function `search-destination`이 대신 호출한다. 앱은 이 함수만 호출한다.

### 3-3. 나라 검색 → 도시 확장

- 결과가 '나라'일 때는 `destinations` 테이블에서 같은 국가코드의 프리셋 도시를 먼저 보여준다.
- 프리셋에 그 나라 도시가 없으면 검색 소스에 '\[나라 이름\] 주요 도시'를 한 번 더 질의해 도시 후보를 채운다.
- 국내는 광역시·도 단위가 아니라 도시·여행지 단위(서울, 부산, 제주, 강릉, 여수, 경주 등)로 보여준다.

## 4. 검색으로 고른 도시의 데이터 매핑

프리셋 도시와 동일하게 앱 기능(환율, 날씨, 브리핑, 장소 추천)이 동작해야 하므로, 검색 결과를 아래 형태로 정규화한다.

| 필드 | 출처 |
| --- | --- |
| 도시명(한국어/영어) | 검색 결과 |
| 국가코드(ISO 2자리) | 검색 결과 |
| 위도·경도 | 검색 결과 (날씨, Places Nearby에 사용) |
| 시간대(`timezone`) | Open-Meteo 응답, 또는 좌표로 시간대 조회. 푸시 알림·브리핑 시각 계산에 필요 |
| 통화 | 국가코드 → 통화 매핑 테이블(`country_currency`)로 결정. 환율 카드에 사용 |
| 지역 탭 | 국가코드 → 지역 매핑 테이블로 결정 (없으면 '기타') |

- 사용자가 한 번 고른 검색 도시는 `destinations`에 `source='user'`로 저장해, 같은 도시를 다른 사용자가 검색할 때도 빠르게 나오게 한다 (캐시 겸용). 개인정보는 들어가지 않는다.
- 운영자가 `source='user'` 도시를 검토해 프리셋(`source='preset'`)으로 승격할 수 있다.

## 5. 데이터 모델

- `destinations`: id, name\_ko, name\_en, country\_code, region(탭 키), lat, lng, timezone, currency, place\_id(nullable), source('preset'|'user'), sort\_order, created\_at
- `country_currency`: country\_code(PK), currency\_code, region
- 읽기는 로그인한 모든 사용자 허용, 쓰기는 `search-destination` Edge Function(service role)만 한다. RLS로 직접 쓰기 차단.
- 기존 `trips`의 여행지 필드는 가능하면 `destination_id`로 연결하되, 기존 데이터(문자열)는 마이그레이션 없이도 동작하도록 호환 유지한다.

## 6. 화면 변경

- 여행지 선택 화면: 가로 스크롤 탭(10개 + 국내)이 되므로 모바일에서 탭 줄이 스크롤되고 선택 탭이 보이도록 자동 스크롤한다.
- 검색창은 탭 위쪽에 고정. 검색어가 있으면 탭 대신 검색 결과 목록을 보여준다.
- 결과 항목: 도시명(한국어), 보조 문구(영문명·국가), 프리셋 여부 표시. 결과 없음일 때는 '다른 이름으로 검색해 보세요' 안내.

## 7. 예외·성능

- 입력 2글자 미만은 검색하지 않는다 (한글 1글자 도시가 없는 것은 아니므로 한국어는 1글자도 허용 여부 확인).
- 같은 검색어 결과는 앱 내 메모리 캐시, 서버는 `destinations` 캐시를 사용해 외부 API 호출을 줄인다.
- 사용자당 분당 호출 제한을 Edge Function에 둔다 (남용 방지).
- 외부 API 실패 시 프리셋 결과만이라도 보여주고 '검색 연결이 불안정해요' 토스트를 띄운다.
- 동음 이명(예: 산호세 - 미국/코스타리카, 시드니 - 호주/캐나다)은 국가명을 같이 표시한다.

## 8. 개발 단계 제안

1. `destinations`, `country_currency` 테이블과 프리셋 시드 데이터 (10개 지역)
2. 지역 탭 UI 확장 (프리셋만으로 동작)
3. `search-destination` Edge Function + 검색창 연동 (메인 소스 + 폴백)
4. 나라 → 도시 확장, 검색 도시 저장·캐시
5. 기존 기능(환율·날씨·브리핑·푸시 시간대)이 검색 도시에서도 동작하는지 확인

## 9. 확인이 필요한 사항

- 국내 탭을 따로 둘지, 현재 구조에서 국내 여행지를 어떻게 다루고 있는지
- 검색 소스 최종 선택(Google Places 단독 vs 폴백 병행)과 예상 호출량
- 프리셋 도시 목록 확정 (위 표는 제안 예시)
- 하와이·괌·사이판 등의 탭 소속
