# Deploy (Vercel) 상세

> CLAUDE.md에서 이동된 상세 내용. 이 영역을 작업하기 전에 먼저 읽을 것.

- **Deploy (Vercel)**: the site is plain static files published from the `triplog/` folder.
  - Run `vercel` / `vercel --prod` from inside `triplog/`, not the repo root (or `serve.py`, `CLAUDE.md`, `supabase/` and everything else would be published).
  - `triplog/vercel.json`: `framework`/`buildCommand`/`installCommand` are `null` (no install, no build); it also sets `X-Content-Type-Options: nosniff` on everything, `Cache-Control: public, max-age=86400` on `/img/*`, and `Cache-Control: no-cache` on `/sw.js` (PRD v11, 웹 푸시 서비스 워커 — see **Web Push**; without this, Vercel's default static-asset caching could keep browsers on a stale service worker file for longer than the browser's own ~24h daily update check). There is no `api/` folder. Almost every route is a `#/...` hash route, so `/` → `index.html` is enough — the exceptions are the Naver login callback, the account-deletion request page, and the admin page, which all need a real (non-hash) path; see **Login page**, **Account deletion request page (계정 삭제 요청)**, and `docs/features/screen-admin.md`. `vercel.json`'s `rewrites` maps the extensionless `/auth/naver-callback` to `triplog/auth/naver-callback.html`, `/account-deletion` to `triplog/account-deletion.html`, and `/admin` to `triplog/admin.html` (Vercel doesn't resolve a directory-style clean URL to `index.html` on its own here); `serve.py` does the same extensionless → `.html` fallback itself for local/phone testing, generically for *any* matching path (`NoCacheHandler._rewrite_clean_url` — not hardcoded per-route), so both environments serve the same file at the same path. `/admin`'s `<meta name="robots" content="noindex, nofollow">` keeps it out of search engines, but that's cosmetic only — real access control is the page's own login+`is_admin()` check plus DB-level RLS, not the route being "secret".
  - File names are case-sensitive on Vercel: keep the paths in `index.html` exactly equal to the real file names.
  - Do not add a `Referrer-Policy: no-referrer` header: the Google Maps key is restricted by HTTP referrer.
  - For a new domain: add `https://<domain>/*` to the Google Maps key's website restrictions, `https://<domain>/**` to Supabase → Authentication → URL Configuration → Redirect URLs (ideally also Site URL), and the domain to the Kakao app (see **Invite**). Otherwise the map is blocked and login returns to the Site URL. Avoid wildcard `*.vercel.app` for the Maps key: any site on vercel.app could use it.
